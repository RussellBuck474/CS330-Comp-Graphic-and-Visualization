Design Reflection
How I Approach Designing Software:
I approach software design by breaking large problems into smaller, manageable components and identifying the core functionality before focusing on details. I rely heavily on modular thinking—defining clear responsibilities for each part of the system and ensuring that every component can be developed, tested, and improved independently. I also use visual references and sketches to clarify structure before writing code, especially in graphics‑focused projects.

New Design Skills Developed During This Project:
Working on the 3D scene strengthened my ability to design modular graphics systems, where each object in the scene is built from reusable functions. I also improved at translating 2D reference images into 3D structures, which required spatial reasoning, proportion analysis, and iterative refinement. This project helped me better understand how to design with transformations, coordinate systems, and hierarchical relationships in mind.

Design Process Followed:
My design process followed a consistent cycle:

Analyze the reference image to understand shapes, proportions, and layout

Break the scene into modular components (platform, towers, turrets, walkway, etc.)

Plan transformations for each component

Build and test each module individually

Integrate components into the full scene

Refine proportions and alignment through iteration

This structured approach kept the project manageable and allowed me to adjust individual parts without disrupting the entire scene.

Applying These Tactics in Future Work:
These tactics—modular design, iterative refinement, and reference‑driven planning—apply to almost any future software project. Whether I’m building a UI, designing a backend system, or modeling a 3D environment, the same principles help maintain clarity, reduce complexity, and support long‑term maintainability.

Development Reflection
How I Approach Developing Programs
I approach development by starting with a working foundation and gradually layering in complexity. I prefer to get something simple running first, then expand functionality through small, testable increments. I also rely on debugging tools, console output, and visual inspection to validate behavior as I build.

New Development Strategies Used in This Project
This project pushed me to use:

Incremental rendering—building one object at a time and verifying transformations

Reusable drawing functions to avoid duplication

Consistent coordinate planning to keep objects aligned

Lighting and camera experimentation to improve scene clarity

These strategies helped me manage complexity and maintain control over the scene as it grew.

How Iteration Factored Into Development
Iteration was essential. Nearly every part of the scene required multiple passes—adjusting heights, widths, rotations, and positions until the structure matched the reference image. Iteration also helped refine lighting, camera angles, and object proportions. Each improvement built on the last, and the scene gradually became more polished and cohesive.

How My Development Approach Evolved Across Milestones
Early milestones focused on understanding OpenGL basics and getting simple shapes on the screen. As the project progressed, my approach became more structured and modular. I shifted from experimenting with individual shapes to designing full components, then integrating them into a complete scene. By the final milestone, I was thinking more like a graphics developer—planning transformations, organizing code, and refining visual details with intention.
